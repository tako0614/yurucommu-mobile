# Yurucommu Mobile

English: [README.en.md](README.en.md)

Yurucommu Mobile は、Yurucommu family のサーバーにつなぐ、フィード中心の Tauri 製モバイルクライアントです。
Takosumi からのインストール引き継ぎ、製品の Deploy to Cloudflare フロー、信頼できる QR、手入力の
HTTPS URL のいずれかでサーバーに接続できます。

Yurucommu は各自が自分用にデプロイする一人用のソフトウェアです。モバイルからも自分の
サーバーへ接続します。連合の通信相手やコミュニティの参加者は、サーバーの所有ユーザーでは
ありません。この製品前提を shared Core や Yurumeet に適用しません。

現在のユーザー、フィード、保存した投稿、未読数は、サーバーの応答を検証してから表示します。
不正な応答を空のフィードとして成功扱いにせず、更新時のエラーとして伝えます。日時のない
投稿は日時を補わず表示し、リモートの投稿者名は公開 API の規則で正規化します。保存した投稿の
失敗は画面内で再試行できます。投稿成功は投稿 ID を確認してから扱い、結果が不明なら下書きを
残して自動再送しません。認証済み引き継ぎのないブラウザ操作は表示しません。

通常のフィード更新では、入力中の本文・公開範囲と送信中の状態を保持します。送信開始後の
編集や明示的なクリアを、遅れて届いた投稿応答で上書きしません。投稿の送信済み表示と
フィード再取得の結果は別に扱い、再取得の失敗で自動再投稿しません。接続先や認証が
変わった場合と再ログイン後は、新しいセッションへ古い応答を反映しません。

ログインは、サーバーが広告する OIDC PKCE フローとホストのパスワードセッションの両方に対応します。
どちらの方式でも、製品 API を呼ぶ前に失効可能なホスト bearer token に交換されます。

## 始め方

この repo の隣に standalone `mobile-kit` checkout が `../mobile-kit` として必要です。

```sh
bun install --frozen-lockfile
bun run mobile:check
```

アプリの製品 API contract は公開 package `@takosjp/yurucommu-api`、モバイル共通基盤は
独立 repo の `@takosjp/mobile-kit` を使います。Takosumi source checkout には依存しません。
OIDC は接続先が `/.well-known/yurucommu` で広告する operator 登録済み native public client
だけを使い、要求 scope は `openid profile` に限定します。

この Tauri shell は iOS / Android 専用です。desktop では Yurucommu web client を使ってください。

## リリースチェック

- `bun run mobile:native-release-check` — Android/iOS の生成プロジェクト、製品所有の secure keystore と
  APNs/FCM の配線、ローカルの native toolchain がすべて揃っていることを厳密に確認します
- `bun run mobile:release-evidence-check` — operator 私有の署名・ストア・実機・OIDC・push の証跡を確認します

## リンク（Takosumi から開く・画面へのリンク）

Takosumi は、このアプリを専用アプリとして開くとき、信頼できる専用アプリの一覧
（`com.yurucommu`、scheme `yurucommu`）にある雛形に画面のURLのoriginを URL encode して入れ、次のどちらかを送ります。

- `yurucommu://connect?host_url=<origin>`
- `yurucommu://connect?host_url=<origin>&product=yurucommu`

アプリはどちらも受け付けます（自動ではサインインしません）。

- サインインしていなければ、そのサーバーを見つけてサインインの手前まで進みます。
- 別のサーバーにサインイン中なら、今のセッションはそのまま使えるようにしたまま、そのサーバーを「別の接続先」として
  出し、保存したアカウントへの切り替えか、サインインして追加するかを利用者が選びます。黙って切り替えません。
- 同じサーバーにサインイン中なら、何も尋ねずにアプリを開くだけです。

画面へのリンク `yurucommu://open?path=/…`（`host_url=` 付きも可）と `yurucommu://open?url=https://<サーバー>/…` は、
接続中のサーバーと同じoriginの絶対pathだけを受け付けます。http(s) 以外のURL、別のoriginへ解決されるもの
（`//host`、`/\host`）、空白・制御文字、2,048文字を超えるものは、開く前に拒否します。認証情報らしい名前
（`code`・`token`・`access_token`・`session`、`…_token` など）の query・fragment・path 引数を持つものも
拒否しますが、これは名前の一覧と語尾による best effort の検査で、ほかの名前に入った認証情報は通ります。
`/join?code=…` のように `code` を使うリンクも開きません（mobile-kit の `allowRouteCodeParameter` は使っていません）。
query・fragment・path 引数の名前は英数字などのASCIIに限ります。全角の英字はASCIIにそろえてから判定し、それ以外の
ASCIIでない名前（`?名前=…` など）を持つリンクは開きません。似た文字で認証情報の名前を作れないようにするためです。
値やアンカーにASCIIでない文字があるのは構いません。

- `/`（フィード。Takosumi の画面のURLはこれ）と `/bookmarks` は、ホームのフィードと保存した投稿で開きます。
- `/notifications` はアプリ内の通知一覧、`/post/<URLエンコードしたAP ID>` は通知先の投稿で開きます。
  一覧の続きはサーバーのcursorで読み込み、失敗は画面内で再試行できます。投稿から戻っても一覧や編集中の下書きを保ちます。
  「再試行」は失敗した続きをやり直し、「再読み込み」は先頭から更新します。
  接続先・アカウントの切り替えや画面の破棄後に、古い応答で表示を上書きしません。
- それ以外の画面はアプリに無いため、ホームのままで「リンク先の画面はアプリにありません」と知らせます。認証済みの
  ブラウザ引き継ぎが無いので、外部ブラウザでは開きません。
- 別の保存済みサーバーへのリンクは、そのサーバーを出して利用者の切り替えを待ち、切り替えた後に開きます。
  サインインしていなければ、サインインの後に開きます。
- 通知をタップしたときも同じ安全検査とアカウントの導線を使います。`event_id` だけの通知は通知一覧へ、
  同じサーバーの投稿pathがある通知はその投稿へ進みます。別originのURLへBearerを渡したり、外部ブラウザを開いたりしません。

これはアプリ内のsource/portable動作です。OS別のpush配送、実端末のcold/warm起動、署名とストア配布は別に検証します。

通常のフィードと保存した投稿のプレビューでも「投稿を開く」からアプリ内の詳細へ進めます。
別サーバーの投稿IDも接続中サーバーを通して読み込み、外部ブラウザへは渡しません。
読取の失敗はその場で再試行でき、「戻る」で編集中の本文を残して元のカードへ戻ります。
詳細を開いている間にフィードを更新してカードが置き換わっても、同じカードへフォーカスを戻します。

投稿詳細から「投稿を保存」「保存を解除」を操作できます。サーバーから確認できた保存状態だけを使い、
変更中の連打を防ぎます。確定した応答を受けて表示と保存した投稿の一覧を更新し、本文の下書きを保ちます。
保存結果が不明な場合は自動再送せず、ボタンを止めて「再読み込み」で現在の状態を確認できます。
接続先・アカウントの変更や画面から戻った後に、古い操作結果を新しい投稿へ反映しません。
投稿詳細に保存状態を返さない旧サーバーでは、この操作は表示しません。サーバー側の対応が必要で、
未対応の状態を「未保存」と推測しません。既存サーバーの更新やCore packageの公開は、このApp変更だけでは行われません。

ホーム、保存した投稿、通知と投稿詳細の読取は、応答ヘッダーだけでなく本文の受信にも15秒の期限を
適用します。期限切れを空の結果にせず、再試行できるエラーとして表示します。戻る操作や画面破棄、
アカウントの切り替えで不要になった通信を中止し、遅い応答を新しい表示へ反映しません。
ホームの並列読取の一つが失敗した場合も、残りの通信を中止し、途中までの結果を完成したホームとして扱いません。

ストアのIDが決まるまで、Takosumi 側の画面の Interface には `clients` を書きません。universal link・App Links
（配布者のドメイン）も未設定です。

## 投稿の添付

フィード、保存した投稿、通知から開く投稿で画像・動画を表示できます。「画像を表示」または
「動画を表示」を押してから読み込み、失敗した添付はその場で再試行できます。動画は自動再生しません。
接続中サーバーの正規media経路だけに本人資格を送り、公開の外部mediaには送りません。
非公開の添付を端末の一時URLとして表示し、接続先・アカウントの切り替えや画面の破棄時に解放します。
不正なURLや非対応の形式は表示できないことを明示します。

本文と一緒に画像・動画を8件まで添付できます。選択したファイルはSDKの形式・サイズ検証後に順番に
アップロードし、日本語の元の名前を画面と投稿に残します。待機・処理中・完了・失敗を表示し、失敗は
明示的に再アップロードするか、その添付を下書きから外せます。本文はサーバーの契約どおり必須です。
期限切れの添付は送信せず、再アップロードを求めます。応答が不明なら本文と添付を残して自動再送しません。
送信中に編集した次の本文や追加ファイルは前の投稿のACKで消さず、受理済みの添付だけを解放します。
クリア、アカウント変更、画面破棄では保留中の処理を中断し、遅い応答を採用しません。
下書きから外してもサーバー上のmediaを直接削除しません。未使用アップロードの保持・回収は既存のサーバー側処理が担います。
これはsource/portable動作で、OS別のファイル・動画対応と実サーバーでの利用確認は別です。

## 通知の配信設定

ビルド時に `VITE_YURUCOMMU_NOTIFICATION_PUSHER_GATEWAY_URL` に公開の notification pusher gateway URL を
設定します。プロバイダ credential は gateway 側にだけ置き、アプリには決して同梱しません。
