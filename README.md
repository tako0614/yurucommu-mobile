# Yurucommu Mobile

English: [README.en.md](README.en.md)

Yurucommu Mobile は、Yurucommu family のサーバーにつなぐ、フィード中心の Tauri 製モバイルクライアントです。
Takosumi からのインストール引き継ぎ、製品の Deploy to Cloudflare フロー、信頼できる QR、手入力の
HTTPS URL のいずれかでサーバーに接続できます。

Yurucommu は各自が自分用にデプロイする一人用のソフトウェアです。モバイルからも自分の
サーバーへ接続します。連合の通信相手やコミュニティの参加者は、サーバーの所有ユーザーでは
ありません。この製品前提を shared Core や Yurumeet に適用しません。

現在のユーザー、フィード、保存した投稿、未読数は、サーバーの応答を検証してから表示します。
不正な応答を空のフィードとして成功扱いにせず、更新時のエラーとして伝えます。日時のない
投稿は日時を補わず表示し、リモートの投稿者名は公開 API の規則で正規化します。保存した投稿の
失敗は画面内で再試行できます。投稿成功は投稿 ID を確認してから扱い、結果が不明なら下書きを
残して自動再送しません。認証済み引き継ぎのないブラウザ操作は表示しません。

通常のフィード更新では、入力中の本文・公開範囲と送信中の状態を保持します。送信開始後の
編集や明示的なクリアを、遅れて届いた投稿応答で上書きしません。投稿の送信済み表示と
フィード再取得の結果は別に扱い、再取得の失敗で自動再投稿しません。接続先や認証が
変わった場合と再ログイン後は、新しいセッションへ古い応答を反映しません。

ホームの読取中に資格やAPI接続先を変更すると、古い読取を中止し、その終了を待たずに
現在の接続で読み始めます。以前の呼出しへ新しい接続の結果は返しません。
同じ接続で重なった更新は引き続き順番に処理し、最後に求めたホームを返します。

ログインは、サーバーが広告する OIDC PKCE フローとホストのパスワードセッションの両方に対応します。
どちらの方式でも、製品 API を呼ぶ前に失効可能なホスト bearer token に交換されます。

## 始め方

この repo の隣に standalone `mobile-kit` checkout が `../mobile-kit` として必要です。

```sh
bun install --frozen-lockfile
bun run mobile:check
```

アプリの製品 API contract は公開 package `@takosjp/yurucommu-api`、モバイル共通基盤は
独立 repo の `@takosjp/mobile-kit` を使います。Takosumi source checkout には依存しません。
OIDC は接続先が `/.well-known/yurucommu` で広告する operator 登録済み native public client
だけを使い、要求 scope は `openid profile` に限定します。

この Tauri shell は iOS / Android 専用です。desktop では Yurucommu web client を使ってください。

Androidの「戻る」は、表示中のプロフィール・編集画面・投稿・通知・検索で、画面内の
戻る操作と同じ処理を使います。入力中の下書きや検索語を保持し、保存処理中は編集画面を
閉じません。ホームではアプリの戻るlistenerを解除してOS標準の操作へ戻します。
接続・解除に失敗した場合は画面内に表示し、「Androidの戻る操作を再接続」から明示的に
再試行できます。解除が成功するまではOS標準の戻る操作の復帰を保証できません。
この動作のsource/portable検証と、実機でのキー・ジェスチャー操作の検証は別に扱います。

### Androidをコマンドから起動する

Android SDK/NDK、RustのAndroid target、生成済みAndroid projectと、接続済み実機または
起動済みemulatorを用意した環境では、Android Studioを開かずに起動できます。
`<device-name>`にはTauriが検出する端末名を指定します。省略するとCLIで起動先を選びます。

```sh
bun run tauri:android:dev "<device-name>"
```

実機から開発サーバーへLAN経由で接続する場合は、到達可能な開発ホストのIPを明示します。
`--host`は端末名に続けて指定でき、共通Vite設定へ`TAURI_DEV_HOST`として渡されます。

```sh
bun run tauri:android:dev "<device-name>" --host "<dev-host-ip>"
```

Android Studioで操作したい場合だけ、`--open`を追加してください。

```sh
bun run tauri:android:dev --open --host "<dev-host-ip>"
```

## リリースチェック

- `bun run mobile:native-release-check` — Android/iOS の生成プロジェクト、製品所有の secure keystore と
  APNs/FCM の配線、ローカルの native toolchain がすべて揃っていることを厳密に確認します
- `bun run mobile:release-evidence-check` — operator 私有の署名・ストア・実機・OIDC・push の証跡を確認します

組立済みAPKは、Android SDKと`unzip`／`readelf`のある環境で静的検査できます。
`<build-tools-dir>`には、使用するSDKの`build-tools/<version>`ディレクトリを指定してください。

```sh
bun run inspect:android-apk -- /path/to/app.apk --build-tools <build-tools-dir>
```

製品sourceのアプリID・version・起動schemeと、APKのFCM service・非debug設定・署名状態・
native library・16 KiB alignmentを照合します。署名が必須なら`--require-signed`、
別のELF読取toolを使うなら`--readelf /path/to/llvm-readelf`を指定できます。
署名なしは明示して返し、署名付きでも配布者の鍵の確認や実OS／OIDC／Push／storeの資格にはしません。
APKを署名・install・公開せず、元のnative／release gateも置き換えません。

## リンク（Takosumi から開く・画面へのリンク）

Takosumi は、このアプリを専用アプリとして開くとき、信頼できる専用アプリの一覧
（`com.yurucommu`、scheme `yurucommu`）にある雛形に画面のURLのoriginを URL encode して入れ、次のどちらかを送ります。

- `yurucommu://connect?host_url=<origin>`
- `yurucommu://connect?host_url=<origin>&product=yurucommu`

アプリはどちらも受け付けます（自動ではサインインしません）。

- サインインしていなければ、そのサーバーを見つけてサインインの手前まで進みます。
- 別のサーバーにサインイン中なら、今のセッションはそのまま使えるようにしたまま、そのサーバーを「別の接続先」として
  出し、保存したアカウントへの切り替えか、サインインして追加するかを利用者が選びます。黙って切り替えません。
- 同じサーバーにサインイン中なら、何も尋ねずにアプリを開くだけです。

画面へのリンク `yurucommu://open?path=/…`（`host_url=` 付きも可）と `yurucommu://open?url=https://<サーバー>/…` は、
接続中のサーバーと同じoriginの絶対pathだけを受け付けます。http(s) 以外のURL、別のoriginへ解決されるもの
（`//host`、`/\host`）、空白・制御文字、2,048文字を超えるものは、開く前に拒否します。認証情報らしい名前
（`code`・`token`・`access_token`・`session`、`…_token` など）の query・fragment・path 引数を持つものも
拒否しますが、これは名前の一覧と語尾による best effort の検査で、ほかの名前に入った認証情報は通ります。
`/join?code=…` のように `code` を使うリンクも開きません（mobile-kit の `allowRouteCodeParameter` は使っていません）。
query・fragment・path 引数の名前は英数字などのASCIIに限ります。全角の英字はASCIIにそろえてから判定し、それ以外の
ASCIIでない名前（`?名前=…` など）を持つリンクは開きません。似た文字で認証情報の名前を作れないようにするためです。
値やアンカーにASCIIでない文字があるのは構いません。

- `/`（フィード。Takosumi の画面のURLはこれ）と `/bookmarks` は、ホームのフィードと保存した投稿で開きます。
- `/notifications` はアプリ内の通知一覧、`/post/<URLエンコードしたAP ID>` は通知先の投稿で開きます。
  一覧の続きはサーバーのcursorで読み込み、失敗は画面内で再試行できます。投稿から戻っても一覧や編集中の下書きを保ちます。
  「再試行」は失敗した続きをやり直し、「再読み込み」は先頭から更新します。
  接続先・アカウントの切り替えや画面の破棄後に、古い応答で表示を上書きしません。
  ホーム表示前に受けたリンクも、別sessionを選んだ時点で破棄します。元の保存済みsessionへ戻っても再実行しません。
  同じsessionでホームの読込をやり直す間は、保留したリンクを維持します。
- それ以外の画面はアプリに無いため、ホームのままで「リンク先の画面はアプリにありません」と知らせます。認証済みの
  ブラウザ引き継ぎが無いので、外部ブラウザでは開きません。
- 別の保存済みサーバーへのリンクは、そのサーバーを出して利用者の切り替えを待ち、切り替えた後に開きます。
  サインインしていなければ、サインインの後に開きます。
- 通知をタップしたときも同じ安全検査とアカウントの導線を使います。`event_id` だけの通知は通知一覧へ、
  同じサーバーの投稿pathがある通知はその投稿へ進みます。別originのURLへBearerを渡したり、外部ブラウザを開いたりしません。

これはアプリ内のsource/portable動作です。OS別のpush配送、実端末のcold/warm起動、署名とストア配布は別に検証します。

通常のフィードと保存した投稿のプレビューでも「投稿を開く」からアプリ内の詳細へ進めます。
別サーバーの投稿IDも接続中サーバーを通して読み込み、外部ブラウザへは渡しません。
読取の失敗はその場で再試行でき、「戻る」で編集中の本文を残して元のカードへ戻ります。
詳細を開いている間にフィードを更新してカードが置き換わっても、同じカードへフォーカスを戻します。

投稿詳細から「投稿を保存」「保存を解除」を操作できます。サーバーから確認できた保存状態だけを使い、
変更中の連打を防ぎます。確定した応答を受けて表示と保存した投稿の一覧を更新し、本文の下書きを保ちます。
保存結果が不明な場合は自動再送せず、ボタンを止めて「再読み込み」で現在の状態を確認できます。
接続先・アカウントの変更や画面から戻った後に、古い操作結果を新しい投稿へ反映しません。
投稿詳細に保存状態を返さない旧サーバーでは、この操作は表示しません。サーバー側の対応が必要で、
未対応の状態を「未保存」と推測しません。既存サーバーの更新やCore packageの公開は、このApp変更だけでは行われません。

ホーム、保存した投稿、通知と投稿詳細の読取は、応答ヘッダーだけでなく本文の受信にも15秒の期限を
適用します。期限切れを空の結果にせず、再試行できるエラーとして表示します。戻る操作や画面破棄、
アカウントの切り替えで不要になった通信を中止し、遅い応答を新しい表示へ反映しません。
ホームの並列読取の一つが失敗した場合も、残りの通信を中止し、途中までの結果を完成したホームとして扱いません。

ストアのIDが決まるまで、Takosumi 側の画面の Interface には `clients` を書きません。universal link・App Links
（配布者のドメイン）も未設定です。

## App内の検索

フィードの「投稿・ユーザーを検索」から、接続中サーバーの投稿とユーザーを検索できます。
検索は明示送信で行い、入力するたびには通信しません。`#タグ` は既存のタグ専用APIで検索します。
結果から投稿・プロフィールを開き、戻ったときも検索語・結果・続き位置とホームの投稿下書きを保ちます。
失敗時は空の結果として扱わず、元の検索や続きページを明示的に再試行できます。
再試行中も、新しく入力した未送信の検索語を上書きしません。

Web版と同じ `/search?search=<検索語>&tab=posts` と `tab=users` のリンクをApp内で開けます。
tabのないリンクはWeb版と同じく両方の検索結果を確認し、ユーザーが見つかればユーザー、なければ投稿を開きます。
コミュニティのtabは未対応として知らせます。外部サーバーへの検索配送やWebFinger取得をこの操作で追加せず、
接続先の既存検索APIが返す範囲を表示します。アカウント・API接続先の変更時には旧検索を退役し、
結果や検索語を次のアカウントへ持ち越しません。OS別実機・正規ログイン・配布の検証は別です。

## 投稿の添付

フィード、保存した投稿、通知から開く投稿で画像・動画を表示できます。「画像を表示」または
「動画を表示」を押してから読み込み、失敗した添付はその場で再試行できます。動画は自動再生しません。
接続中サーバーの正規media経路だけに本人資格を送り、公開の外部mediaには送りません。
非公開の添付を端末の一時URLとして表示し、接続先・アカウントの切り替えや画面の破棄時に解放します。
不正なURLや非対応の形式は表示できないことを明示します。

本文と一緒に画像・動画を8件まで添付できます。選択したファイルはSDKの形式・サイズ検証後に順番に
アップロードし、日本語の元の名前を画面と投稿に残します。待機・処理中・完了・失敗を表示し、失敗は
明示的に再アップロードするか、その添付を下書きから外せます。本文はサーバーの契約どおり必須です。
期限切れの添付は送信せず、再アップロードを求めます。応答が不明なら本文と添付を残して自動再送しません。
送信中に編集した次の本文や追加ファイルは前の投稿のACKで消さず、受理済みの添付だけを解放します。
クリア、アカウント変更、画面破棄では保留中の処理を中断し、遅い応答を採用しません。
下書きから外してもサーバー上のmediaを直接削除しません。未使用アップロードの保持・回収は既存のサーバー側処理が担います。
これはsource/portable動作で、OS別のファイル・動画対応と実サーバーでの利用確認は別です。

## 通知の配信設定

ビルド時に `VITE_YURUCOMMU_NOTIFICATION_PUSHER_GATEWAY_URL` に公開の notification pusher gateway URL を
設定します。プロバイダ credential は gateway 側にだけ置き、アプリには決して同梱しません。

## 投稿の会話と返信

投稿詳細から返信一覧を読み、続きはサーバーのcursorで取得します。読取の失敗はその場で再試行でき、
表示できる返信がない途中ページを会話の終端として扱いません。返信を開いて戻ると、元の一覧と続きの位置を保ちます。

通常のNoteには、フィードと同じ画像・動画付きの返信フォームを使えます。親の実応答から返信先・公開範囲・
コミュニティを確認し、不明な値から公開投稿を推測しません。コミュニティへの返信は同じIDを送ります。
フォロワー限定の親では、返信先は元の投稿者のフォロワーと一致しないため、自分のフォロワーかダイレクトを明示的に選びます。
ダイレクトは本文の明示mentionをサーバーの既存actor APIで確認してから送ります。「投稿者を宛先に追加」は本文を編集する操作で、
黙って宛先を付け足しません。宛先不明や異なるhostの応答ではPOSTしません。

作成ACKに返信先がない現行Coreでは、同じ15秒の期限内に投稿IDを接続先サーバーで再読込し、親・投稿者・公開範囲・
コミュニティの結合を確認します。確認不能な結果は下書きを残し、自動で再送しません。確定した投稿と、返信一覧の更新失敗は分けて表示します。
戻ると返信の下書き・添付を保ったまま不要な通信を中止します。別の投稿へ移るときは未送信の返信を黙って破棄しません。
アカウント変更・画面破棄では資格の異なる下書きと一時URLを退役します。Storyなど公開先の契約が異なる投稿や不明なcontextは、返信の読取にとどめます。

これはsource/localの動作です。サーバーへの保存、相手による読取、外部への連合配送、OS別実端末は別の証拠として扱います。

完全修飾の自サーバーmentionはCore側の解決修復を必要とします。旧Core packageの更新・既存サーバーへの採用は、このApp source変更だけでは行いません。返信の保存確認を、相手による受信や外部配送の確認と同一視しません。

### 投稿のいいねと状態確認

フィード・保存した投稿・投稿詳細・返信のカードで、接続中のサーバーの本人状態に基づく
いいね／解除を行えます。サーバーが本人の `liked` を返さない場合は状態未確認と表示し、
明示的な状態確認が成功するまで変更操作を表示しません。数値は保存後の投稿 GET から採用し、
クライアントで加減算しません。変更 ACK と保存状態の読み込みは同じ15秒の予算内です。

応答欠落・不正な ACK・権限拒否・保存状態との不一致では結果を確定せず、変更操作を止めます。
「いいねの状態を確認」は読み込みのみ行い、自動で再送しません。同じ投稿のカードは
処理中・結果不明・確認済みの状態を共有し、別カードから二重送信しません。変更前に
開始した古い読み込み応答が後から届いても、確認済みの本人状態や件数を巻き戻しません。同じ投稿の最後の表示カードを離れたときや
接続アカウントが変わったときは旧リクエストを中止し、遅れて届いた結果を採用しません。
中止はサーバー側の変更取消しを保証しないため、戻ったカードでは必要に応じて状態を確認します。

この機能のportable／ローカルHTTP／ブラウザfixture検証は、実端末のOS動作、正規ログイン、
稼働サーバーへの導入、通知配信やストア配布の資格とは別です。

### App内のプロフィール

フィード・保存一覧・投稿詳細・返信・通知の投稿者から、接続中のサーバーを通して
プロフィールと投稿一覧を開けます。自分のプロフィール、共有された `/profile`・
`/profile/<識別子>`・`/users/<ユーザー名>` のリンクもApp内で扱います。
他のサーバーへ資格を渡したり、ログイン済みブラウザがあると仮定して外部ページを開いたりしません。

プロフィールの投稿一覧は続きの読み込み・再試行・詳細からの戻る操作に対応します。
元の画面の投稿下書きと、プロフィール内の返信下書きは独立して保持します。
別のプロフィールへ移る際に返信の下書き・添付・未確認の送信結果があるときは、
破棄を確認します。サーバーが返さない件数を0と表示せず、不明として扱います。
本人と相手の正規プロフィールを確認したうえで、フォロー・申請取消・解除を行えます。
承認待ちと承認済みを区別し、変更後は保存済みの状態と件数を再取得します。
結果が不明な場合は再送せず「フォロー状態を確認」から復帰します。画面を閉じたり
別の相手に移っても未確認の結果を保持し、本人や接続先の切替時には前の操作を退役させます。
サーバーが関係状態を提供しない場合や自分自身には変更操作を許可しません。
リモート相手への配送には接続先サーバーの連合機能が必要で、App内のローカル検証は配送の証明ではありません。

### 自分のプロフィールを編集

既存の「自分のプロフィールを開く」から、表示名・自己紹介・アバター・ヘッダー画像・承認制フォロー・追加項目を編集できます。
追加項目は4件まで、名前と内容は各255文字、表示名は50文字、自己紹介は500文字です。
画像はJPEG・PNG・GIF・WebPを既存media APIへアップロードし、URLの指定や削除もできます。
変更した項目だけを保存し、正規の本人確認・保存応答・保存済みプロフィールの再読込が一致してから完了を表示します。
日本語などの変換中のEnterでは保存しません。変換を終えた後の「保存」や通常のEnterによる保存は使えます。自己紹介の通常Enterは改行を入力します。
保存中に入力した次の変更は残します。結果不明時は入力を保持し、明示的な状態確認なしに再送しません。
現在の保存状態を確認しても、入力中の新しい変更を上書きしません。入力の破棄には確認があります。
下書きは同じアカウントのメモリ内に保持し、接続アカウントの変更時には旧操作を退役します。

プロフィール画像は明示操作で読み込みます。接続先の正規media経路だけに本人資格を送り、実応答の画像形式とサイズを確認して表示します。
公開の外部画像には資格を送らず、非表示になったプロフィールの読取と一時URLを解放します。
プロフィールの保存、読み直した現在値、ホームの更新、連合配送は別の結果です。
このAppのローカル検証は、実機・正規ログイン・稼働サーバーへの配備や外部配送の証明ではありません。

投稿詳細では、現在の本人が投稿者と一致する場合だけ「投稿を削除」を表示します。
確認後に本人を読み直し、既存の本人限定DELETEへ送信します。成功応答に加えて
同じサーバーで投稿が見つからないことを確認してから一覧へ戻り、ホーム・保存一覧・
プロフィールを更新します。返信の下書き・添付・送信中の返信がある間は削除できません。
失敗・結果不明のときは詳細を残し、自動再送せず、投稿の再読み込みを求めます。
画面やアカウントが変わった後の古い応答は、新しい画面や一覧を上書きしません。
これはAppのsource/portable動作で、OS・実サーバー・ActivityPub配送の確認とは別です。

本人の投稿詳細では「投稿を編集」から本文と内容警告をその場で保存できます。
表示用HTMLから本文を復元せず、接続中サーバーが返す元の文字列を使います。
本文は5000文字、内容警告は500文字までで、変更した項目だけを既存PATCHへ送り、
警告を外すときは空文字を使います。公開範囲・宛先・添付は変更しません。
保存中の追加入力を残し、結果不明なら再送せず、明示的なGETで現在値を確認します。
閉じた編集を同じ投稿で開き直すと入力を保持し、別の投稿へ移る際は未保存の編集を確認します。
確認済みの本文は会話・プロフィール・ホーム・保存一覧へ反映し、古い読取で戻しません。
接続先APIだけを切り替えた場合も旧scopeの操作を退役させます。
保存前の読取で既に変更された項目を検出しますが、元APIには排他更新がなく、
その読取後に走る別writerとの競合は防げません。これらはAppのsource/local検証で、実機や配備の資格とは別です。

内容警告（CW）のある投稿は、ホーム・保存一覧・詳細・返信・プロフィールで本文と添付を
最初は閉じて表示します。「内容を表示」で開き、「内容を隠す」で閉じられます。
添付の読込は開いた後も既存の明示操作が必要です。開閉状態は各カード内だけに持ち、
投稿内容・警告・添付・接続先・アカウントが変わったときや画面を離れたときは閉じ直します。

ホームは「以前の投稿を読み込む」で20件より前の投稿へ進めます。サーバーの続き位置を
そのまま使い、重複する投稿は追加しません。読込失敗時は今の投稿と投稿下書きを残し、
明示的な「続きを再試行」で同じ位置を読み直します。画面を離れると保留中の読込を中断し、
ホームの新しい取得・接続先・アカウントの変更後に古いページを追加しません。
確認済みの編集・削除は追加ページにも反映します。続き情報のない旧応答は最初のページを
表示しますが、続きや終端を確認できたとは扱いません。これはsource/localの動作で、実機・配備とは別です。
